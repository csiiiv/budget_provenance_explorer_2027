# Standalone validation

The standalone deployment publishes static Vite output, not the original
data extraction environment. Validate the actual shipped files before
assuming an explorer works. Run validation on PRs and manually; it does not
gate Pages deployment until known migration defects are resolved.

## Layers

| Layer | Command (from repo root) | Contract |
| --- | --- | --- |
| Bundle integrity | `python3 web/tests/check_integrity.py fmr` (also `nia`, `dpwh`) | Required files, unique IDs, count/amount reconciliation, link integrity, checksums |
| Public browser | `python3 web/tests/check_public_site.py fmr` | Actual project-pages subpath, assets, load, search, drawer, nav |
| Public browser routes | same command with `nia`, `nia-titles`, `nia-map`, `dpwh`, `about` | Each route independent; basemap tiles mocked for deterministic CI |
| Public evidence | same command with `public-docs` | NIA package attribution and public link contract |
| Historical regression | `python3 web/check_smoke.py` | FY2027 FMR documented edge cases, including corrections, realignments and uncertain matches |
| Lineage audit | `python3 web/tests/check_lineage.py` | Original SHA-256 values, registered inputs, acyclic registry, explicit missing inputs |

Build first: `npm --prefix web ci && npm --prefix web run build`.
For browser tests install `playwright==1.55.0` in Python and Chromium
if system Chrome is absent. Use the existing original DPWH and NIA scripts
as historical references; they are not run automatically because they
encode fixed counts and/or local filesystem assumptions.

## Known migration defects (not waived)

- DPWH: `web/public/data/dpwh.json` is gitignored and not generated by
  Pages. Several required exporter inputs are also excluded. Both DPWH jobs
  should fail until a real, complete bundle is available at the deployment
  path. Do not replace it with an empty placeholder or weaken the test.
- NIA: supporting-docs attribution is present, but package links are
  `file://` URIs. The public evidence check should fail until links are
  redesigned; the upstream Drive folder does not prove per-file public access.
- Lineage: the original registry reports four inherited mismatches (two DA
  drafts and raw/mapped Annex A-4). The audit reports actual and recorded
  hashes. Do not overwrite original hashes to make CI green; reconcile the
  sources and record reviewed revisions.
- Missing upstream source files are named explicitly in the lineage audit.
  They are not verified; use `--strict` when all original inputs are available.

## Test maintenance

Use current bundle controls for counts and amounts. Keep named project cases
as historical regression fixtures with documented evidence, not generic
application requirements. Do not test CSS color values in functional tests.
Prefer accessible labels and semantic selectors. A passing bundle check
shows internal consistency, not independent verification of source truth;
source reconstruction requires the excluded upstream files.

CI currently runs separately on PRs and manual dispatch. After the above
defects are fixed and the new suite is green, consider gating deployments
on the independent required checks. Historical data re-extraction and
visual regression should remain distinct from the production smoke suite.
